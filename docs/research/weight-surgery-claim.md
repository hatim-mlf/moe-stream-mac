# “Weight surgery” on Qwen3.5-4B: source check and local relevance

**Research checked 2026-11-04.** This is a source and method review. No model weights were downloaded, and no code or model files were changed.

## Finding in brief

The first public source I found for the specific **Qwen3.5-4B** numbers is [Zeng Jiajun’s X post from Nov. 2, 2026](https://x.com/zengjiajun_eth/status/2117409198686216574). [Md Ismail Šojal’s X post](https://x.com/0x0SojalSec/status/2117749121159512465) and the [Facebook post shown in the supplied screenshot](https://www.facebook.com/0xSojalSec/posts/claude-opus-55-just-edited-performed-targeted-weight-surgery-on-qwen35-4b-and-bo/1672038127783917/) repeat it. Zeng’s [Nov. 3 update](https://x.com/zengjiajun_eth/status/2117655549877567705) calls the result “targeted ablation,” not self-improvement, and says a similar edit on a 125B FP4 model was mostly lost to rounding and did not beat a runtime projection.

I found **no public 4B edit script, weight diff/checkpoint, named 150-question evaluation set, per-question results, or detailed protocol** linked from those posts or in searches of GitHub, Hugging Face, arXiv, and r/LocalLLaMA. That means the exact 4B result is **not independently reproducible from the material I found**. The closest complete public source is an earlier, materially different experiment on Qwen3.5-0.8B by Rikiya Takehi and coauthors. Its [write-up](https://rikiyat.github.io/blog/weight-space-programming/), [experiment logs and code](https://github.com/RikiyaT/lm_understand-logs/tree/main/exp8_math), and [edited model card](https://huggingface.co/RikiyaT/Qwen3.5-0.8B-weight-space-programming) make that experiment inspectable; they do not verify the 4B numbers.

The screenshot’s claim is therefore **plausible in outline, but unverified in its specific model, edit, evaluation, and “zero human intervention” details**. Anthropic’s [Opus 5.5 page](https://www.anthropic.com/claude-opus-5-5) confirms the model exists; I found no Anthropic account of this experiment. The public 0.8B experiment used GPT-6 Astra through Codex CLI, not Claude Opus 5.5.

## What the public experiments actually show

Takehi, Teoh, Zhang, and Khattab’s Nov. 2 post describes an agent using forward-pass observations to write a weight-edit script for Qwen3.5-0.8B. The successful `p50c` run used a Python sandbox over the checkpoint, a budget of 50 forward passes, and practice problems drawn from GSM8K train, MATH train, and AIME answers. The model did not see the benchmark questions. There were no gradients or optimizer-based training loop. The setup did include human-provided corrections about tool facts and pass size, plus a harness requiring the agent to explain its steps, so it does not establish “zero human intervention” as a general property.

The published `p50c` edit subtracts a repetition direction from **64 output columns in each of two MLP `down_proj` matrices**, at layers 15 and 19: `2 × 64 × 1,024 = 131,072` weights, reported as 0.016% of the 0.8B model. This is not the claimed 4B edit of two columns in layer 29. The public rebuild script and checkpoint hashes make the 0.8B edit auditable.

For that 0.8B model, the write-up reports MATH-500 accuracy moving from 7.9% to 48.1%, GSM8K from 13.8% to 67.1%, and IFEval from 21.0% to 62.3%; MATH-500 token-limit hits fell from 93% to 33.1%. The Hugging Face card includes a rerun and the edit artifact. Those are striking results, but they are results for a different model, edit, and evaluation protocol. The same write-up also reports that a Gemma 3 270M attempt did not establish a reliable math improvement and notes that an edit can remove an obstacle without supplying missing reasoning ability.

Qwen’s [official Qwen3.5-4B config](https://huggingface.co/Qwen/Qwen3.5-4B/blob/main/config.json) lists 32 layers and hidden size 2,560. Thus layer 29 and two hidden-width output columns are structurally possible. Two columns of 2,560 weights are about 5,120 weights, which is roughly 0.00012% of a 4.27B-parameter denominator. The percentage is arithmetically plausible, but without the exact tensor, parameter denominator, edit diff, or script it cannot authenticate the reported operation. I found the official base checkpoint, but no edited 4B checkpoint from the named author.

## Arithmetic and controls

The post reports 59 correct answers out of 150 at baseline, then 92–94 after the edit. That is a gain of **33–35 answers**, or **22.0–23.3 percentage points** (39.3% to 61.3–62.7%). Removing 22–25 loop failures could account for at most 22–25 newly correct answers if each loop was a wrong baseline response and each was fully fixed. The reported gain is therefore **8–13 answers larger** than the loop count. That remainder needs another explanation—such as other errors changing, different sampling, or scoring variation. The counts alone do not show which explanation applies. “Almost doubled” also overstates the ratio: 92–94 is about 1.56–1.59 times 59.

The reported random patch scores, 47–57, are all below the 59-answer baseline. They show that the particular random patches reported did not match the targeted score, but do not by themselves establish a sound control. The post does not report the number of random draws, random seeds, norm/quantization matching, whether sampling and grading were identical, or uncertainty and paired per-question outcomes. A same-shape patch can still have a very different effective size or simply damage the model. Without those details, the control cannot separate a meaningful targeted effect from a weak or harmful random intervention.

“Held-out” is not independently checkable for the 4B claim: the post does not name or link the 150 problems, give item identifiers, or show overlap checks. The public 0.8B experiment names MATH-500 and publishes artifacts, but that does not make the 4B set public or prove that its examples were held out from the edit process.

## Related work and what it does—and does not—support

- **Refusal direction / abliteration.** [Arditi et al., “Refusal in Language Models Is Mediated by a Single Direction” (2024)](https://arxiv.org/abs/2406.11717) identify and ablate a refusal-related residual-stream direction in several open chat models. Adding or removing it changes refusal behavior, including refusals on harmless prompts. This supports the possibility of changing a behavior with a narrow direction; it also demonstrates meaningful side effects. The paper’s activation ablation is not itself proof of a particular weight-space edit. “Abliteration” is a later label often used for related weight edits.
- **Representation engineering and activation addition.** [Zou et al. (2023)](https://arxiv.org/abs/2310.01405) study population-level representations for monitoring and control. [Turner et al. (2023)](https://arxiv.org/abs/2308.10248) construct contrast-derived activation directions and add them during inference. These provide direct precedent for measuring contrast-pair activations and testing a reversible runtime intervention before editing quantized weights.
- **Repetition neurons.** [Hiraoka and Inui (2025)](https://arxiv.org/abs/2410.13497) compare FFN activations before and after repetitions across many generations. Ablating selected neurons can suppress repeated tokens and outputs, while activating them can increase repetition. The effect depends on model and language; deactivation can harm perplexity, and effects are not uniform across model sizes. This supports a testable repetition mechanism, not a universal “loop direction” or guaranteed accuracy improvement.
- **Reasoning loops.** [Pipis et al. (ICML 2026)](https://arxiv.org/abs/2512.12895) analyze looping in reasoning models and connect it to easy cyclic actions and temporally correlated errors. Their findings caution against assuming all loops arise from one shared neuron direction. Temperature changes can reduce visible loops without fixing the underlying error. [Doan et al. (2025)](https://arxiv.org/abs/2507.07810) further study how repetition neurons interact with induction heads and in-context learning, with layer-dependent effects.
- **ROME/MEMIT.** [ROME (Meng et al., 2022)](https://arxiv.org/abs/2202.05262) and [MEMIT (Meng et al., 2022)](https://arxiv.org/abs/2210.07229) edit factual associations in feed-forward layers, with tests for specificity and generalization. They are useful precedents for measuring edit scope and side effects, but they target factual memories rather than a general instruction-following policy or reasoning habit.

Taken together, the literature supports the narrower claim that some behaviors are represented in directions or a small set of components and can be perturbed. It does not support treating every coding failure as a removable direction, nor does it guarantee that a direction edit preserves unrelated behavior.

## Relevance to our Qwen3.6-35B-A3B helper

Our helper is a 40-layer Qwen3.6-35B-A3B MoE in MLX 4-bit, with Gated DeltaNet and gated-attention layers, 256 routed experts, top-8 routing, and a shared expert. The actual failure analysis is in [DIAGNOSIS.md](../finetune/DIAGNOSIS.md). It identifies spec drift/invented behavior/omissions, ignored or partly applied review notes, API/return-shape misuse, bounds errors, and unused code. **It does not identify reasoning loops as a failure mode.** The 4B claim’s layer 29 or its two-column edit should not be transplanted to this model.

### Failure types worth a direction experiment

1. **Ignored or partly applied review notes.** This is the clearest policy contrast: for the same prompt, compare a completion that follows every supplied note with one that ignores or only partly applies it. A direction might increase the tendency to attend to and implement explicit review constraints. It cannot make an absent or ambiguous note unambiguous.
2. **Spec drift, invented behavior, or omitted requested content.** Contrast completions that stay within the request with completions that add unsupported semantics or omit requirements. A direction might shift the model toward constraint fidelity. It cannot determine requirements the prompt never states, and improvements must be checked for over-literal or incomplete answers.
3. **API/return-value/data-shape misuse, conditionally.** Try this only where the prompt or supplied code contains the relevant API contract and a correct response is already in the model’s demonstrated capability. A direction might favor checking and preserving a stated contract. It cannot teach a missing API fact or an unknown library behavior. Bounds errors and unused code are lower-priority direction targets; execution checks, compiler feedback, and focused retries are more direct for those.

Missing knowledge, algorithms, and facts are not created by projecting away a direction. The most plausible gain is a change in which already-available behavior the model selects, not new competence.

### A concrete, low-memory pilot

1. **Build paired examples without touching the frozen evaluation prompts.** Use non-held-out training/validation attempt records and fresh synthetic coding tasks. Keep the user prompt, code context, and review note identical within each pair. Label one answer as correct and complete and the other as the relevant failure. Do not use any prompts from the frozen held-out manifest to compute directions, pick layers, or tune strength. Hold out separate development pairs for choosing the layer and scale.
2. **Capture the residual stream.** Teacher-force each completion through the same model and collect activations at the output of each of the 40 decoder blocks, after the block’s residual updates. Use assistant-answer token positions, with a fixed or matched answer window; do not mix in internal DeltaNet state or individual expert activations for the first pass. Sweep the block outputs rather than assuming the layer from Qwen3.5-4B transfers.
3. **Compute a supervised direction.** For each matched pair and layer `l`, calculate `δᵢ,l = mean(answer activations for goodᵢ) − mean(answer activations for badᵢ)`. Normalize pair deltas and average them, then normalize the mean to get `d_l`. Check a PCA direction over the same pair deltas as a stability comparison, with its sign set toward the good examples. Prefer the paired mean difference as the first, interpretable estimate.
4. **Steer at inference first.** During answer generation, after the selected block, try `h ← h + α d_l` on generated assistant tokens. Sweep a few low strengths scaled to that layer’s residual RMS. This is reversible and leaves the 4-bit weights intact. Select layer and strength on development pairs only.
5. **Evaluate with paired controls.** Run baseline, the selected direction, and several random unit directions at the same layer and matched activation scale, on the exact frozen prompts and settings in [`tools/ft_eval.py`](../../tools/ft_eval.py) and [`tools/ft_eval_manifest.json`](../../tools/ft_eval_manifest.json). Use its review-note mode and paired result comparison; inspect per-task regressions as well as aggregate success. The manifest has only eight held-out tasks, so treat it as a regression check rather than a precise estimate of general capability. The evaluator currently supports model endpoints and LoRA adapters, not a residual-steering hook; a future experiment would need a temporary MLX endpoint/hook or evaluator integration. No such code change is part of this research task.
6. **Only consider a weight edit after runtime evidence.** In logical matrix notation, if a chosen module’s output writer `W` maps into the residual stream, one possible partial projection is `W′ = (I − λddᵀ)W`. The actual MLX tensor orientation and module writers must be checked before applying it. For this hybrid MoE, possible writers include attention/DeltaNet output projections and the shared and routed expert down projections; the right site is an empirical question. Editing many expert writers is a substantially broader change than two columns in one dense layer. Dequantizing and requantizing 4-bit weights can erase small edits or introduce collateral changes. Zeng’s 125B FP4 update is a direct warning to compare against runtime projection first.

### Memory and engine fit

This method needs **forward passes and activation summaries only**: no gradients, backward pass, optimizer, or training loop. Accumulate per-layer sums and, if using PCA, second-moment summaries online, then discard each prompt’s activations. The summary vectors are tiny compared with model weights or a training optimizer state. The MLX hybrid engine already streams experts for inference, as described in the [project README](../../README.md) and [hybrid engine](../../engine/hybrid/hybrid.py), so this does not require the roughly 27 GB training memory that blocked fine-tuning. The current engines do not expose the needed per-block residual taps, however; a future pilot needs a small activation-capture/steering hook in the MLX path. This report makes no code changes.
